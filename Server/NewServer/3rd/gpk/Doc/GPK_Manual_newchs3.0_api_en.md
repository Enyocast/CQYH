# GPK SDK API reference from the Chinese manual

This translates section 7, pages 14–18, of `GPK_Manual_newchs3.0.pdf`. Names and signatures are retained as printed, except for obvious spacing introduced by PDF extraction. Where the source contradicts itself, the discrepancy is identified; check the SDK headers and implementation before relying on it.

## 7.1 Namespace

The GPK module uses the `SGPK` namespace.

## 7.2 `GPKStart`

Automatically updates the GPK component, starts the kernel protection process, and creates a component. The source description names `IGPKSvrDynCode`, but the declaration and return description name `IGPKCltDynCode`.

```cpp
IGPKCltDynCode* GPK_API GPKStart(IN LPCSTR UpdateServerURL, IN LPCSTR GameCode);
```

- `UpdateServerURL`: update-server URL. Pass `NULL` to skip updating, mainly for debugging and testing. The source parameter description calls this `UpdateServer`.
- `GameCode`: game code, up to eight bytes plus a terminating `\0` (nine bytes total).
- Returns the `IGPKCltDynCode` interface pointer on success or `NULL` on failure.

## 7.3 `GPKCreateSvrDynCode`

```cpp
IGPKSvrDynCode* GPK_API GPKCreateSvrDynCode();
```

Creates the server component. There are no parameters; it returns its interface pointer on success or `NULL` on failure.

## 7.4 `IGPKSvrDynCode`

This server component supports dynamic encryption and decryption and updating the dynamic algorithm library without restarting the server.

### `LoadBinary`

```cpp
int GPK_API LoadBinary(const char* pszSvrBinDir, const char* pszsCltBinDir);
```

Loads dynamic-code file pairs. The arguments are the server and client dynamic-code directories, respectively. Returns the number of pairs loaded on success or `-1` on failure.

### `Release`

```cpp
void GPK_API Release();
```

Releases the component; there are no parameters or return value.

### `AllocAuthObject`

```cpp
IGPKCSAuth* GPK_API AllocAuthObject();
```

Creates an `IGPKCSAuth` object for a connection session. Returns its pointer on success or `NULL` on failure; there are no parameters.

## 7.5 `IGPKCltDynCode`

This client component provides dynamic-algorithm encryption and decryption and protects the integrity of the GPK kernel module.

### `SetDynCode`

```cpp
bool GPK_API SetDynCode(const unsigned char* lpDynCode, int nLen);
```

Sets the GPK dynamic-code data and must be called before the first dynamic encryption or decryption. `lpDynCode` points to the `sndc` data received from the server; `nLen` is its length. Returns `true` on success and `false` on failure.

### `Release`

```cpp
void GPK_API Release();
```

Releases the component; there are no parameters or return value.

### `ProcessAuth`

```cpp
Int GPK_API ProcessAuth(void* Object, fnGPK_CltCallBack SendToSvr,
                        unsigned char* lpData, unsigned long nLen);
```

Processes CSAuth data sent by the server. `Object` is a callback object pointer, whose type depends on the game architecture and may be a socket, user object, or `NULL`. `SendToSvr` is the callback; the source parameter description instead calls it `SendToClt`. `lpData` is the input/output data pointer and `nLen` is the data length. A positive return is the processed length; otherwise processing failed. The source prints the return type as `Int`.

## 7.6 `IGPKCSAuth`

This server component detects malicious software and the GPK working state.

### `GetAuthData`

```cpp
Int GetAuthData(const unsigned char** ppDataRet, void* Object,
                fnGPK_SvrCallBack SendToClt = NULL);
```

Generates CSAuth data. `ppDataRet` is the data pointer. `Object` is a callback object pointer whose type depends on the game architecture and may be a socket, user object, or `NULL`; `SendToClt` is the callback. A positive return is the data length, `-1` indicates an exception, and `0` means the client did not respond to repeated authentication checks, potentially because a cheat blocked the packets. The source prints the return type as `Int`.

### `CheckAuthReply`

```cpp
int CheckAuthReply(const unsigned char** ppDataRet,
                   unsigned char* lpData, unsigned long nLen);
```

Checks Auth data returned by the client. The source describes `ppDataRet` as the CSAuth data pointer, `lpData` as the output data pointer, and `nLen` as the data length. See `GPK_CHECK_INFO` for return values; verify the buffer direction against the headers and implementation.

### `GetCSAuthDynCode`

```cpp
int GetCSAuthDynCode(const unsigned char** ppCodeRet);
```

Obtains dynamic-code data ready to send to the client. `ppCodeRet` receives the pointer to data generated by the function; set `*ppCodeRet` to `NULL` beforehand. On success, the return is the positive data length.

### `Release`

```cpp
void GPK_API Release();
```

Releases the component; there are no parameters or return value.
